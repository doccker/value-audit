# value-audit

> 在继续烧 token 之前，先回答：**这个项目凭什么收钱？**

**别人验证的是你嘴里的 idea，本工具审计的是你仓库里的代码。**
确定性画像采集、结论落到具体文件路径、改进建议按 git diff 跨审计核销——它审的是你项目的
真实状态，不是你对项目的描述；且全程在你本地运行，代码与商业事实不上传任何服务器
（可选的匿名使用统计默认关闭，字段白名单见下文"隐私与匿名统计"）。

value-audit 是一个 [pi](https://github.com/earendil-works/pi) 扩展。在任意项目目录执行 `/value-audit`，
它会采集项目画像、对照内置的价值审计方法论，产出一份《价值审计与路演准备报告》：

- 🚦 **审计结论**（红/黄/绿灯）——包括敢于告诉你"这个方向别做了"的红灯机制
- 🧭 **核心逻辑提炼**——从代码而非 README 提炼"为谁把什么变成什么、钱在哪一步"
- 💰 **商业建议**——付费方、定价逻辑、差异化、风险，以及"持久盈利运转模型"（收入/留存/成本/渠道/壁垒五环，
  结合联网检索的同类盈利模式基准，指出最弱一环）
- 👀 **用户观测就绪检查**——确定性检测项目有没有手段看到"用户用了哪些模块"（内置埋点或
  GA4/百度统计/Umami/PostHog 等）；没有就按技术栈与用户地域给出一天能接完的最小事件集与工具建议
- 🔧 **代码改动 backlog**——从"展示能力"到"承担结果"的具体改法，带稳定 ID，可跨审计核销
- 🎤 **投资人问答稿**——32 道天使投资人常问问题 + 基于项目实际情况的回答与缺口清单

适用时机（越具体越有效）：准备融资/路演前、项目做了几个月还没人付费时、决定要不要继续投入时。
不限技术栈与项目类型，但它对"要回答收钱问题"的项目才有价值——纯公益/纯学习项目不需要它。

完全免费。

## 五条产品原则

1. **零打扰**：全程不问问题（唯一例外：代码无变化时确认是否重跑）。能从代码、README、git
   历史推断的信息自动推断；推断不了的落到报告缺口清单，事实档案填不填由你决定，不填也能出报告。
2. **诚实优先**：每个结论标注来源——`[代码证实]`（附文件路径）/ `[用户提供]`（来自你填写的事实档案）/
   `[联网检索]`（附来源 URL 与日期，只采信权威来源）/ `[待验证]`（只给回答框架和验证动作，**绝不编造数字**）。
3. **敢亮红灯**：如果审计发现"用户本来就不做这件事"或"停用后没人痛"，报告不会生成粉饰性的
   路演答案，而是直接给出转向建议。一个只会夸你的审计工具不值得存在。
4. **迭代闭环**：审计 → 按 backlog 改代码 → 复审。复审基于 git diff 核销 backlog、对比灯色变化，
   而不是失忆重来。
5. **不借焦虑运营**：驱动你复审的只有真实的进度（backlog 核销、距下一灯色的真实缺口）与
   真实的停用损失（你积累的审计档案）。本工具永不做连续打卡、倒计时施压、FOMO 通知、
   羞辱式对比——审计工具靠说真话留住你，不靠焦虑绑架你。

## 安装

```bash
pi install git:github.com/doccker/value-audit
```

试用（不安装）：

```bash
pi -e git:github.com/doccker/value-audit
```

## 使用

```
/value-audit             # 执行审计（首次生成事实档案模板；完成后自动打开档案目录）
/value-audit focus 定价  # 聚焦某个主题的审计（定价/壁垒/渠道…）
/value-audit note <文本> # 记录决策/现实反馈到决策日志，下次审计作为证据，复审时对照"预测→实际"
/value-audit todo        # 查看未核销的改动建议（按优先级）
/value-audit do B3       # 把某条 backlog 交给当前 agent 执行（验证类出访谈脚本/取数步骤，代码类做最小改动）
/value-audit list        # 所有项目的灯色汇总（多项目/机构场景）
/value-audit where       # 查看档案路径
/value-audit open        # 打开档案目录
/value-audit export [目录] # 导出报告（默认到当前目录，显式动作不算污染）
```

本地开发/多项目试用：`pi install /本地/仓库/路径`（路径安装不复制文件，改完代码 `/reload` 生效）。

> 两种安装方式**只能保留一种**。同时安装会在启动时报
> `Tool "value_audit_save" conflicts with ...`，此时执行 `pi remove git:github.com/doccker/value-audit`
> 或 `pi remove /本地/仓库/路径` 去掉其中一个即可（也可直接编辑 `~/.pi/agent/settings.json` 的 `packages` 数组）。

典型工作流：

1. 首次执行 `/value-audit`，得到报告 + 事实档案模板 `facts.md`
2. 填写 facts.md（用户数、团队、定价等代码里看不出的事实）
3. 重跑 `/value-audit`，问答稿标记升级
4. `/value-audit do <ID>` 逐条推进 backlog，提交后再跑，报告自动生成"变化对比"节，核销已完成项

## 产物位置

所有产物存放在你的用户目录下，**不污染项目代码**：

```
~/.value-audit/projects/<项目名>-<hash>/     # Windows: %USERPROFILE%\.value-audit\...
├── VALUE-AUDIT.md    # 最新报告
├── facts.md          # 你的商业事实档案（只增不改）
├── journal.md        # 决策日志（/value-audit note 追加）
├── state.json        # 审计状态（backlog 核销、历次结论）
└── history/          # 每次审计的报告快照
```

项目身份：git 仓库按根提交识别（移动目录不丢档案）；非 git 项目按绝对路径识别（移动 = 新档案）。

自定义知识层：在 `~/.value-audit/knowledge/` 放你自己的 .md（行业基准、补充题库），审计时自动追加在内置知识库之后。

## 方法论来源

内置知识库蒸馏自三份材料（见 `knowledge/`）：

- **价值审计七问**：用户为"少承担麻烦"付费、寻找"靠人硬撑的流程"、停用损失决定付费意愿
- **PMF 生存检查表**：价值主张、差异化、商业模式、渠道、合规、成本结构等 12 维度
- **投资人提问地图**：问题 / 人 / 解 / 钱 四组 32 题

## 已知边界

- 分析质量取决于你在 pi 中使用的模型；本工具负责框架、证据采集和输出结构，不负责判断力本身
- 联网检索能力取决于会话内可用的工具（搜索/浏览器类 MCP，或 bash curl）：不引入任何搜索 API key，
  检索失败时对应内容退回 `[待验证]`，不影响报告产出
- 大型仓库的画像采集做了截断，细节由 agent 按需读取

## 隐私与匿名统计

- 审计全程在本地运行，代码、报告、商业事实永不上传。
- 匿名使用统计**默认关闭**：首次审计完成后询问一次，`/value-audit stats on|off` 随时更改。
- 开启后**只上报**：匿名随机 ID、工具版本、事件名（审计开始/审计完成/保存失败/子命令使用）、
  审计序号、灯色、子命令名（固定枚举，如 todo/list）、错误类别（固定枚举）、操作系统平台。
- **绝不上报**：项目名/路径、代码、报告/facts/journal 内容。
- 上报失败静默忽略，不影响任何功能。

## 反馈问题

遇到 bug、审计质量问题或功能建议，请提 [GitHub Issue](https://github.com/doccker/value-audit/issues)，建议附上：

- 工具版本（package.json 的 version）与操作系统
- 问题现象（报告片段请自行脱敏，不要贴含商业机密的内容）
- 复现步骤（如能提供）

审计结论不符合预期时，先确认 facts.md 是否如实填写——工具的诚实度取决于输入的诚实度。
